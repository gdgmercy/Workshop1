Welcome

In the next 90 minutes, you’ll turn your resume into a real website that anyone can visit. On the way, you’ll learn the tools professional developers use every day: VS Code, Git and GitHub.

What you’ll build

A one-page portfolio at your own address, https://your-username.github.io. You’ll improve it with a series of pushes, and your live site updates after each one.

What you need

  • A Windows laptop or a Mac. Chromebooks and iPads won’t work for this workshop.
  • Your resume as a PDF or Word file. No resume? Your basic details are enough.
  • About 90 minutes. No coding experience needed.

How to use this guide

Do one step at a time. Read the whole step before you start, copy commands exactly, and only move on when your screen matches the green “You should see” box. If something goes wrong, open the “Stuck?” box at the bottom of the step.

How websites get built

Every website you visit went through the same four stages. Today you’ll do all four yourself.

  1. DevelopYou write and change files on your laptop, in VS Code.
  2. SaveGit takes snapshots of your files, called commits, so you can always go back.
  3. ShareYou push your commits to a repository on GitHub.
  4. DeployGitHub Pages turns your repository into a live website.

Words you’ll hear today

Terminal
A window where you type commands instead of clicking. VS Code has one built in.
Repository (repo)
A project folder that Git tracks. Your repo lives on your laptop and on GitHub.
Commit
A saved snapshot of your project, with a short message about what changed.
Push
Sending your commits from your laptop up to GitHub.
Branch
A separate line of work, so you can try something without touching the main version.
Pull request (PR)
A page on GitHub that asks to merge a branch’s changes, so they can be reviewed first.
Deploy
Putting your site on the internet so other people can visit it.
Git and GitHub are different things

Git is a tool on your laptop that saves versions of your work. GitHub is a website that stores those versions online. Think of Git as the camera and GitHub as the photo album.

Set up your laptop

This is the slowest step, so if you did some of it at home, great. Check each item anyway.

  1. Open VS Code. Don’t have it? Download it free from code.visualstudio.com and install it with the default options.
  2. Open the terminal. In the menu at the top, choose Terminal → New Terminal. A panel opens at the bottom of the window. This is where you’ll type commands.
  3. Check that Git is installed. Click in the terminal, paste this, and press Enter: 
    git --version
    If you see something like git version 2.50.1, you’re done with this item. If not:

    If it says git is not recognized, download Git from git-scm.com/downloads/win. Run the installer and click Next on every screen without changing anything. Then quit VS Code completely, open it again, and rerun the command.

    A window will pop up asking to install the command line developer tools. Click Install and wait until it finishes, which can take several minutes. Then run the command again.

  4. Create your GitHub account if you don’t have one, at github.com/signup. GitHub emails you a code to verify your address, so have your inbox open. Pick your username carefully, because it becomes your website address. Something close to your real name works best.
  5. Introduce yourself to Git. Git stamps every commit with a name and email. Use the same email as your GitHub account. Run these one at a time: 
    git config --global user.name "Your Name"
git config --global user.email "you@example.com"
  6. Sign in to GitHub in VS Code. Click the Accounts icon (the person shape) near the bottom of the bar on the far left, then Sign in with GitHub (it may say “Sign in to use Copilot”). Approve in the browser window that opens, and let it send you back to VS Code.
You should see

git --version prints a version number, and clicking the Accounts icon shows your GitHub username.

Stuck? Common fixes for this step

I installed Git, but it still says “not recognized”

VS Code was open during the install, so it doesn’t know about Git yet. Close every VS Code window, open it again, and open a new terminal.

The browser sign-in never returns to VS Code

Look for a browser prompt asking to open Visual Studio Code and click Open. If there’s no prompt, go back to VS Code and try signing in again.

GitHub says my email isn’t verified

Find the email from GitHub (check spam) and click the link or enter the code. Pushing and Copilot need a verified email.

Create your project folder

Everything for your website lives in one folder. You’ll also make a private corner of it that never gets uploaded.

  1. Open a new folder in VS Code. Choose File → Open Folder, create a new folder called portfolio (your Documents folder is a good place), select it, and open it. If VS Code asks whether you trust the authors, choose Yes, I trust the authors.
  2. Make a folder called private. In the Explorer panel on the left, hover over PORTFOLIO, click the New Folder icon, type private and press Enter.
  3. Put your resume inside it. Drag your resume file from File ExplorerFinder onto the private folder in VS Code. Then right-click it, choose Rename, and call it resume.pdf (or resume.docx for a Word file).
  4. Open a fresh terminal. Choose Terminal → New Terminal again, so it starts inside your new folder.
  5. Check where your terminal is. Run this, then paste the result into “Check my output” below: 
    pwd
    The last line it prints should end with portfolio.
portfolio
└── private
    └── resume.pdf
Why a private folder?

Your resume has your phone number and address. In step 8, you’ll tell Git to never upload this folder, so your project stays public but your personal details don’t.

2. Leave out my phone number and home address.
3. Never invent anything. If something is missing, use a clear placeholder like [ADD LINK].

Save your work with Git

Now you’ll take your first snapshot. First, though, you’ll tell Git what it should never save.

  1. git initStart tracking this folder. Once per project.
  2. git statusSee what changed and what Git will save.
  3. git add .Choose the changes for your next snapshot. The dot means everything.
  4. git commitTake the snapshot, with a short message.
  1. Create a file called .gitignore at the top level of your folder, not inside private. In the Explorer, click an empty spot, then the New File icon, and type the name exactly, starting with the dot. Paste this in and save with Ctrl SCommand S: 
    # Private files: Git will never upload these
private/

# Clutter your computer creates on its own
.DS_Store
Thumbs.db
    Each line is a file or folder Git should pretend doesn’t exist. Lines starting with # are just notes.
  2. Start tracking your folder: 
    git init
    It replies Initialized empty Git repository. Your files turn green in the Explorer because Git now sees them.
  3. See what Git sees: 
    git status
    Under “Untracked files” you’ll see .gitignore, index.html, script.js and style.css. Notice that private/ is missing. That’s your .gitignore working.
  4. Choose everything and take the snapshot. Run these one at a time: 
    git add .
git commit -m "First version of my portfolio"
Always use -m with a message

The text in quotes is your commit message. Without -m, Git opens a confusing text editor. Good messages say what changed, like “Add dark mode.”

You should see

Running git status again says nothing to commit, working tree clean. Your first snapshot is saved.

Stuck? Common fixes for this step

“Author identity unknown” or “Please tell me who you are”

Run the two git config commands from step 3, then commit again.

“fatal: not a git repository”

The terminal isn’t in your portfolio folder, or you skipped git init. Open a new terminal (step 4) and try again.

private/ shows up in git status

The ignore file has the wrong name or is in the wrong place. It must be called exactly .gitignore, with no .txt on the end, and sit next to index.html. If you already committed it, run git rm -r --cached private and commit again, then ask a helper before you push.

A strange editor filled the terminal

You ran git commit without -m. Press Esc, type :q! and press Enter. Then run the commit command again with -m.

Push and go live

Your snapshot is on your laptop. Now you’ll send it to GitHub and turn it into a real website.

  1. Create your repository. Go to github.com/new and name it exactly: 
    your-username.github.io
    Set it to Public. Leave README, .gitignore and license off, because you already have files. Click Create repository.
  2. Connect your laptop and push. Back in the VS Code terminal, run these one at a time: 
    git branch -M main
git remote add origin https://github.com/your-username/your-username.github.io.git
git push -u origin main
    The first line names your main branch main. The second tells Git where your GitHub repo is. The third uploads your commits.
  3. Approve the sign-in if asked. A “Connect to GitHub” window appears. Choose Sign in with your browser and click Authorize.VS Code says an extension wants to sign in using GitHub. Click Allow.
  4. Refresh your repo page on GitHub. Your files are there, and private isn’t.
  5. Check that Pages is on. On your repo page, open Settings → Pages. Under “Build and deployment,” the source should be Deploy from a branch, with main and / (root) selected. If not, set them and click Save.
  6. Watch it deploy. Open the Actions tab on your repo. A run called “pages build and deployment” turns green after a minute or two.
  7. Open your site: https://your-username.github.io
You should see

Your portfolio, live on the internet. Open it on your phone or send the link to a friend. That’s push 1 done.

Stuck? Common fixes for this step

It asks for a password, or says permission denied or 403

GitHub doesn’t accept your account password here. Make sure you’re using the terminal inside VS Code and you’re signed in to GitHub there. If the error names a different username, this computer remembers another account; see Troubleshooting.

“remote origin already exists”

You already ran the connect command. Fix the address with:

git remote set-url origin https://github.com/your-username/your-username.github.io.git

“Updates were rejected” or “fetch first”

Your repo was created with a README. Combine it with your work, then push:

git pull origin main --allow-unrelated-histories --no-rebase --no-edit
git push -u origin main

“src refspec main does not match any”

You haven’t made a commit yet. Go back to step 8.

The site shows a 404 page

Wait two minutes and refresh. Check the repo name is exactly your username plus .github.io, and that index.html is at the top level.

Polish the design

First versions are rarely beautiful. Now you’re the art director: you pick a direction, and the AI does the detail work.

  1. Pick a direction that fits you: calm and minimal, bold and confident, or warm and friendly.
  2. Paste this into your AI helper, replacing the bracket with your direction: 
    Improve the design of my portfolio. Keep all the text and content exactly the same.

Style direction: [calm and minimal / bold and confident / warm and friendly]

- Refine the typography: a clear size scale, comfortable line height, and strong headings.
- Make the spacing consistent between sections and between elements.
- Choose one accent color that fits the style direction, and use it only for links and small highlights.
- Add subtle hover states to links and buttons.
- Give the page a proper title, a meta description and a simple favicon.
- Don't add gradients, glows, emoji, animations that move on their own, or new sections.

When you're done, explain what you changed in three short bullet points.
  3. Review it in your browser. Refresh the tab with your local site. Ask for small follow-ups until you like it, like “Make the headings a little smaller” or “Use more space between sections.”
  4. Commit and push, one line at a time: 
    git add .
git commit -m "Polish the design"
git push
  5. Check your live site after a minute. If it looks unchanged, do a hard refresh with Ctrl Shift RCommand Shift R.
Hate the new look? Undo it.

This is why you commit. Before you commit, this command throws away every change since your last snapshot:

git restore .
You should see

The new design on your live site, and “2 commits” on your GitHub repo page. Push 2 done.

Dark mode with a pull request

Professional developers rarely change the main version directly. They work on a branch, open a pull request, review it, and then merge. You’ll do exactly that.

  1. BranchA safe copy to experiment on
  2. CommitSave the change on the branch
  3. PushUpload the branch
  4. Pull requestReview what changed
  5. MergeAdd it to main and go live
  1. Create a branch and switch to it: 
    git switch -c dark-mode
    You’re now on dark-mode. Look at the bottom-left of VS Code: it shows the branch name. Your main branch is untouched.
  2. Ask your AI helper for dark mode: 
    Add a light and dark theme switch to my portfolio.
- Put a small, clearly labeled toggle button in the top corner.
- Start with the visitor's system setting, and remember their choice if they change it.
- In dark mode, use dark grey rather than pure black, and keep good contrast for all text and links.
- Don't change any content or the layout.
    Refresh your local site and try the toggle.
  3. Commit and push the branch: 
    git add .
git commit -m "Add dark mode"
git push -u origin dark-mode
  4. Open a pull request. On your repo page, a yellow banner says dark-mode had recent pushes. Click Compare & pull request, then Create pull request.
  5. Review the changes. Open the Files changed tab. Green lines were added and red lines were removed. This view is called a diff, and it’s how teams check each other’s work.
  6. Merge it. Go back to the Conversation tab, click Merge pull request, then Confirm merge.
  7. Bring your laptop up to date: 
    git switch main
git pull
You should see

A working dark mode toggle on your live site after a minute or two. Run git log --oneline to see your history so far. Push 3 done, and the core workshop is complete.

Stuck? Common fixes for this step

There’s no yellow banner

Open the Pull requests tab, click New pull request, and pick dark-mode in the “compare” dropdown.

“Your local changes would be overwritten” when switching branches

You have changes you haven’t committed. Run git add . and git commit -m "Save work", then switch again.

git log filled the screen and I’m stuck

Press q to get back to the prompt.

Troubleshooting

Find the message you see. If nothing here fixes it, raise your hand. Helpers are walking around.

Setup

“git is not recognized” or “command not found: git”

Git isn’t installed, or VS Code was open when you installed it. Install Git (step 3), then quit VS Code completely and open it again.

Mac: “xcrun: error: invalid active developer path”

The developer tools are missing, often after a macOS update. Run this, click Install, and wait:

xcode-select --install
“codex”, “claude” or “agy” is not recognized

Close the terminal with the trash can icon and open a new one. If it still fails, show a helper the PATH line the installer printed.

AI helpers

I hit a usage limit

Switch to another option in step 5. Your files and history don’t change.

The AI made a mess and I want to go back

git restore .

New files the AI created stay behind, so delete those in the Explorer.

Copilot says it can’t create or edit files

Git

“Author identity unknown” or “Please tell me who you are”

Run the two git config commands from step 3, then commit again.

“fatal: not a git repository”

A strange text editor took over the terminal

My private folder shows up in git status

git commit -m "Save work"
“CONFLICT” or “Automatic merge failed”

Two versions changed the same lines, and Git needs you to choose. VS Code highlights the conflict with buttons like Accept Current Change and Accept Incoming Change. If you’re unsure, ask a helper. It only takes a minute to fix together.

Pushing

It asks for a password, or says permission denied or 403

GitHub doesn’t accept your account password for Git. Use the terminal inside VS Code and make sure you’re signed in to GitHub there. If the error names a different username, this computer remembers another account:

  • Open Credential Manager from the Start menu, choose Windows Credentials, remove the entries for github.com, and push again.Open Keychain Access, search for github.com, delete those entries, and push again.

git remote set-url origin https://github.com/your-username/your-username.github.io.git
“Repository not found”

GitHub can’t find the repository in your command. Check that you created it on GitHub, that it’s named exactly your username plus .github.io, and that your username is spelled right. Then fix the address:

git remote set-url origin https://github.com/your-username/your-username.github.io.git
“Could not resolve host” or the push times out

The site loads, but without any styling

The page can’t find style.css. GitHub Pages treats capital letters as different, so Style.css and style.css are different files. Make the file name match the link in index.html exactly, then commit and push.
